## 0. 全局约定

### 0.1 统一响应包

```
{ "success": true, "code": 200, "message": "操作成功", "data": {...} }
```

以 **`utils/BaseResult` + `utils/ResultCodeEnum`** 为准（2026-09-26 定：代码与契冲突看代码，代码与代码看后端）。
注意 `success` 字段是实际存在的 —— 小程序 `utils/api.js:10` 就是靠 `body.success` 判成败的。

| code | success | message | 含义 |
|---|---|---|---|
| `200` | `true` | 操作成功 | 成功 |
| `-100` | `false` | 操作失败 | 业务失败 |
| `-200` | `false` | 参数错误 | 入参不合法 |
| `500` | `false` | 系统错误 | 未捕获异常 |
| `401` | `false` | 未登录 | 未登录（`ResultCodeEnum.UNAUTHORIZED`） |

> `401` 见 [Q1](#附录-a待决问题收口)。**2026-09-27 起由 Shiro 收口**（见 §7.0）：
> 未登录不再走"HTTP 200 + 响应包 `code=401`"，而是**真 HTTP 401** + 响应壳 `code=401`
> （`config/TokenAuthFilter` 写死；等级不足是 HTTP 403 + `code=403`，`config/RoleAuthFilter`）。
> 前端 `utils/api.js` 两种形态都认。

`BaseResult.data` 目前声明为 `Map<String, Object>`。列表/字典类端点天然是 `{items: [...]}` 这种包一层；
详情端点的 `data` **直接就是条目对象本身**（见 §2），实现时把字段装进一个 Map 即可得到同样的 JSON。

### 0.2 JSON 列的口径（2026-09-27 修订）

`docs/spec.md:132`：**数据库的 JSON 列不对小程序透传**，服务端用固定 DTO 组装。
理由是小程序有版本碎片问题，改一个 JSON 内的 key 就会让老版本小程序渲染不出来。

**修订后的具体口径**：`tag` / `effect` 两个 JSON 列**拆成固定字段**下发（`tags` / `raw` + `cooked`），
**但元素里的 `code` 保留数据源原值**（`HUNGER`、`HUNGER_COOKED`）。中文对照表在**服务端**
（效果那份本轮新建），以 `nameZh` 随元素一起下发。

**禁止的是**"整列原样塞进响应"（即 `ItemDto` 现在的 `List<ItemTag> tag` / `List<Effect> effect` 直传结构），
不是"元素里不能出现数据源的原值 code"。

### 0.3 `slug`【已定 2026-09-27】

**计算值，表里没有这一列**（表结构见 CLAUDE.md 数据模型节）。由 `nameEn` 派生 —— `nameEn` 是 upsert 去重口径，天然唯一，所以 slug 也唯一，不必拼 id。

**规则：直接复用 `crawler/IconFileNames` 的文件名规则，再全小写。** 不新造规则。

```java
// 与 IconFileNames.UNSAFE 同一个字符集
slug = nameEn.replace(' ', '_')            // 空格先换成下划线
            .replaceAll("[^A-Za-z0-9._'()-]", "_")  // 白名单外一律换下划线
            .toLowerCase()
```

白名单 `[A-Za-z0-9._'()-]` 是两端约束的交集（URL 路径段无需转义 + 合法文件名），理由见 `IconFileNames.java:24-31`。

**为什么不能"机械剥离"**：库里有两组名字，按常见的"删特殊字符 / 丢括号内容"规则会**硬撞车**（slug 必须唯一）：

| 名字 | 删特殊字符 / 丢括号 → | 本规则 → |
|---|---|---|
| `Bugle` | `bugle` | `bugle` |
| `Bugle?` | `bugle` ❌ 撞 | `bugle_` ✅ |
| `Bugle Shroom` | `bugleshroom` / `bugle-shroom` | `bugle_shroom` |
| `Bugle Shroom (Poisonous)` | 同上 ❌ 撞 | `bugle_shroom_(poisonous)` ✅ |

**已对库里 134 条真实 `nameEn` 实跑验证：134 → 134 个唯一 slug，零撞车。** 只有 `Bugle?` 一条触发了字符改写。

样例：

| nameEn | slug |
|---|---|
| `Hot Dog` | `hot_dog` |
| `Bugle` | `bugle` |
| `Bugle?` | `bugle_` |
| `Bugle Shroom (Poisonous)` | `bugle_shroom_(poisonous)` |
| `Pandora's Lunchbox` | `pandora's_lunchbox` |

> **展示不受影响**：slug 只进 URL。页面标题/列表文字一律取接口返回的 `nameZh` / `nameEn`，**不许拆 URL 反推标题**（否则会显示成 `bugle_`）。

### 0.4 计算字段

| 字段 | 算法 | 出处 |
|---|---|---|
| `slug` | 见 §0.3 | — |
| `primaryType` | 8 取值 `FOOD`/`CONSUMABLE`/`EQUIPMENT`/`DEPLOYABLE`/`AMULET`/`MYSTICAL`/`MISC`/`ENEMY`；类型中含 `food`（**不分大小写**，所以 `Natural food`、`Packaged food` 也算）即 `FOOD`；否则按 `CONSUMABLE > EQUIPMENT > DEPLOYABLE > AMULET > MYSTICAL > MISC` 取首个命中；纯 `Enemy` 归 `ENEMY` | CONTEXT.md 主类型节 |
| `isCookable` | **不用现算**，采集时已写成 `flag=cookable` 标签。**只管生熟两栏数值的显隐**，不是"游戏里能不能烤" | `ItemConverter.java:122` |

三者都不落库。**实现在新建的工具类里**（两个静态方法 `slugOf(Item)` / `primaryTypeOf(Item)`），
缓存组装条目时调一次并随条目一起缓存。

> 数据源原值 `Mystical item` 对应取值 `MYSTICAL`，不是同名重命名。已对库验证：
> 含 `Berry`/`Mushroom`/`Natural food`/`Packaged food` 的条目**全部**同时含 `Food`；5 条 `Amulet` **全部**同时含 `Mystical item`。

### 0.5 三条贯穿性数据约定

- **列表不过滤 `removed` 条目**。`Bugle?`、`Warp Compass` 照常出现 —— 这是明确的产品决定（CONTEXT.md 图鉴条目节）。
- **筛选与搜索在小程序本地做**。`/api/items` 不接受任何筛选参数、一次返全量。好处是零网络往返、切类别与输关键词都即时；代价是筛选逻辑钉在客户端（改一次要发版），且列表剔除了描述，本地搜不到描述里的词。
- **返回顺序**：按 `primaryType` 分组（组序 `FOOD` → `CONSUMABLE` → `EQUIPMENT` → `DEPLOYABLE` → `AMULET` → `MYSTICAL` → `MISC` → `ENEMY`），组内按 `id` 升序。不定顺序的话每次查询的返回次序都可能不同。

## 1. `GET /api/items` 列表

**已定**

- **无参数、不分页**，一次返全部 134 条（含 2 条已移除）
- 响应：`data.items: [...]`

```json
{
  "success": true, "code": 200, "message": "操作成功",
  "data": {
    "items": [
      { "slug": "hot_dog", "nameZh": "热狗肠", "nameEn": "Hot Dog",
        "icon": "/icons/Hot_Dog.png", "weight": 5.0, "primaryType": "FOOD" }
    ]
  }
}
```

| 字段 | 说明 |
|---|---|
| `slug` | §0.3。**列表必须带它** —— 详情页跳转靠它拼 `?slug=` |
| `nameZh` / `nameEn` | 列表要同时显示中英名 |
| `icon` | 相对路径，如 `/icons/Hot_Dog.png` |
| `weight` | 一位小数、可为负 |
| `primaryType` | §0.4。**一级导航就靠这一个字段**，前端在本地按它切格 |

**列表不带的东西**（有意剔除）：

- `description` / `descriptionZh` —— 中文描述最长 391 字，134 条全带会让 payload 从 ~50KB 涨到 ~180KB
- `tags` —— 首期不做二级筛选，带了没人用
- `id` —— 详情用 slug，id 是库内自增、换机器重灌数据会变，下发只会成为噪音
- 不给 `crossModule` 之类的跨界标记 —— 一条记录只有一个 `primaryType`，跨界条目（`Scorpion`）只出现一次（见 CONTEXT.md 图鉴条目节）

## 2. `GET /api/items/{slug}` 详情

**已定**

- 路径参数是 **`slug`**（见 §0.3），不是 `id`
- **`data` 直接就是条目对象**（不再包一层 `item`）
- **只给中文描述** `descriptionZh`；英文 `description` 不下发
- 详情页要能**一屏看到生熟对比** —— 这是该页面最主要的用途（CONTEXT.md 生/熟节）

```json
{
  "success": true, "code": 200, "message": "操作成功",
  "data": {
    "slug": "hot_dog",
    "nameZh": "热狗肠", "nameEn": "Hot Dog",
    "icon": "/icons/Hot_Dog.png", "weight": 5.0,
    "primaryType": "FOOD", "isCookable": true,
    "raw":    [ { "code": "HUNGER", "nameZh": "饥饿", "value": -30.0, "duration": null, "startDelay": null },
                { "code": "BONUS",  "nameZh": "额外耐力", "value": 20.0, "duration": null, "startDelay": null },
                { "code": "USES",   "nameZh": "使用次数", "value": 1.0,  "duration": null, "startDelay": null } ],
    "cooked": [ { "code": "HUNGER", "nameZh": "饥饿", "value": -60.0, "duration": null, "startDelay": null },
                { "code": "BONUS",  "nameZh": "额外耐力", "value": 30.0, "duration": null, "startDelay": null } ],
    "descriptionZh": "热狗肠是 PEAK 中的天然食物……",
    "achievement": "大胃王奖章",
    "tags": [ { "code": "type", "value": "Food", "nameZh": "食物" },
              { "code": "rarity", "value": "Legendary", "nameZh": "传说" },
              { "code": "biome", "value": "Gloom", "nameZh": "雾沼" } ]
  }
}
```

### 2.1 生熟怎么拆

`effect` 是一个**混合数组**，生值和熟值靠 `_COOKED` 后缀区分，且熟值存的是**总量**不是增量。
服务端拆成 `raw` / `cooked` 两个结构相同的数组，元素给出 5 个字段：

| 字段 | 说明 |
|---|---|
| `code` | **已剥掉 `_COOKED` 后缀**。`raw` 和 `cooked` 里出现的可能是同一个 `code`（如 `HUNGER`），各自数组内不重复 |
| `nameZh` | 中文名，来自**服务端新建的效果字典**（见 §8） |
| `value` | 带符号，**负值表示消除/减少该状态**（CONTEXT.md 状态效果节）。前端原样显示（`-30`），不要翻符号 |
| `duration` / `startDelay` | 可空 |

- 不可烹饪时 `cooked` 是**空数组 `[]`**、`isCookable` 为 `false`，前端据此隐藏熟食那一栏
- `HEAT`、`USES`、`INJURY`、`DROWSY` 这类**永远不会有 `_COOKED` 版本**（采集侧只对饱食/加成/毒/刺/孢子生成熟值），
  所以 `cooked` 里没有它们不代表"熟了就没这效果"—— 这是采集口径，不是数据缺失

### 2.2 其余字段

| 字段 | 说明 |
|---|---|
| `tags` | **全量 6 个维度**（type / biome / rarity / source / location / flag），供详情页渲染「生态 / 来源 / 稀有度」展示区（spec story 18） |
| `achievement` | 库内只有 28 条有，没有时为 `null` |
| `descriptionZh` | 中文描述，最长 391 字 |

### 2.3 找不到

返 `code = -100` + 说明性 `message`（如「条目不存在」），**不是** 200 带 `data: null` ——
让前端能区分"没有这条"和"后端挂了"，否则两种情况的用户观感都是白屏。

## 4. `GET /api/tags`

**用途**：给筛选面板渲染标签字典。首期不做二级筛选，所以**现在没有消费方** —— 但小程序
`utils/api.js` 的 `fetchAll()` 会拉它，**接口不存在会导致前端启动直接失败**（`body.success` 取不到 → Promise reject），所以本轮必须实现。

- **返回字典全量**（`crawler/TagDictionary.java:20-29` 就是全部字典），**不查库**
- 6 个维度：`type`（12 个取值）/ `biome`（11）/ `rarity` / `source` / `location` / `flag`（2：`cookable` / `removed`）
- 响应：`data.tags: [{code, value, nameZh}]`，**扁平数组**，元素形状与条目里的 `tags` 元素**完全一致**（前端一套代码认两种）

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "tags": [ { "code": "type", "value": "Berry", "nameZh": "浆果" },
                      { "code": "biome", "value": "Tropics", "nameZh": "雨林" } ] } }
```

## 5. `GET /api/biomes` 生态

- **与 `/api/tags` 的关系**：生态只是 `tag.code = "biome"` 这一个维度。本接口是它的**专用入口**，独立存在是因为前端 `fetchAll` 要它
- **返回字典全量**（`TagDictionary.BIOME_ZH` 的 11 个），**不查库、不带条目数**
- 响应：`data.biomes: [{value, nameZh}]`
- 生态 = "在哪捡到"；来源 = "怎么得到"，两者不要混（CONTEXT.md 生态节）

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "biomes": [ { "value": "Tropics", "nameZh": "雨林" } ] } }
```

## 6. `POST /api/auth/login` 登录（最小版）

**本轮落最小版。** Shiro 过滤链、JWT 签发与 Realm **仍不做**，留给 [#5](https://github.com/shanchahuaA/guide/issues/5)。

- 入参 `js_code`（小程序 `wx.login` 拿到的那个）。openid 由后端带 appid + secret 调 `code2Session` 换
  （`guide-mini/pages/main/main.js:16`）
- 按 openid **upsert** `user` 行：不存在则以 `level = 0` 新建
- **`token` 是占位串**（不签 JWT，值就等于 openid）。这个 key **必须存在** ——

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "openid": "oXXXX", "token": "oXXXX", "level": 0 } }
```

> 依赖：`weixin-java-miniapp` 本轮**首次真正使用**；`jjwt` 仍**零代码使用** ——
> 技术栈验收里 JWT 那条要到 #5 才能指认，本轮指认的是微信登录那条。

## 7. AI 教学（`/api/teach/**`）

**本轮落地。** 这里原先只留了 `POST /api/ai/chat` 的占位，现在拆成一族端点。
词汇（**用户等级** / **AI 教师** / **题库** / **每日路线**）见 `CONTEXT.md`，不在这里重复定义。

模型与配置：DeepSeek 官方 `https://api.deepseek.com`，OpenAI 兼容 `POST /chat/completions`，
`Authorization: Bearer <用户自己的 key>`，模型 `deepseek-flash`（= DeepSeek-V4.1-Flash）。
抽成 `guide.ai.base-url` / `guide.ai.model` / `guide.ai.enabled` 三个配置项（与既有的 `guide.crawler.*` 同一命名习惯）。**不引 SDK**，用 Spring `RestClient` 手写。

### 7.0 贯穿性约定

- **身份**：除 `/api/auth/login` 外，本节所有端点都要求请求头带 `token`（§6 的占位串，值即 openid）。
  **2026-09-27 起由 Shiro 过滤链收口**（`config/ShiroConfig`）：`/api/teach/**` 走 `tokenAuthc`，
  缺 token / 查不到人 → **HTTP 401** + 响应壳 `code=401`。控制器里保留的手工校验只是兜底
  （过滤链被绕过或请求直调时才会触发），不再是主鉴权。
- **等级一律从身份取**：端点**不接受任何 level 参数**。前端传什么都不改变后端认定的等级（防越权）。
- **越级门禁矩阵**（后端硬拦）：

  | 用户等级 | 禁问 |
  |---|---|
  | `0` 菜鸟 | 路线类、速通类 |
  | `1` 入门 | 速通类 |
  | `2` 高手 | 无 |

  拦下的回 `code = 403` + 提示文案，**不调大模型**（内容层；HTTP 仍 200）。`guide-mini/utils/api.js`
  的 reject 分支已经带 `body.message`，前端弹窗即可（`wx.showModal` / `showToast`）。

  文案**按等级分支**（同一句里不能出现"新手"，否则入门用户被叫错）：

  | 用户等级 | 触发 | 文案 |
  |---|---|---|
  | 菜鸟 | 问路线类或速通类 | 这个对新手还是太难了，等成为高手再来吧！ |
  | 入门 | 问速通类 | 速通的事等你成为高手再聊吧！ |

- **越级门禁分两层**（2026-09-27 整合，见 §7.7）：
  - **路径层**在 Shiro 过滤链上：`/api/teach/beginner/**` 要 `beginner`（≥入门）、
    `/api/teach/expert/**` 要 `expert`（仅高手）；不满足 → **HTTP 403** + 响应壳 `code=403`，
    请求不进控制器、不调大模型。它挡的是"手改前端去调高级入口"。
  - **内容层**是 `service/TeachGate`：同一个 `/api/teach/ask` 里按问题分类拦越级（自由文本的兜底），
    拦下 → `code=403` + 上面的文案。它挡的是"把越级问题往 `/api/teach/ask` 里塞"。
  - 两层缺一不可：路径拦不住"把越级问题塞进 `/ask`"，内容层又表达不了"哪条路径归哪一档"。
- **降级**：`guide.ai.enabled = false` 时，`/api/teach/ask` 返回预置文案而不是报错。演示叙事不变。

### 7.1 `GET /api/teach/profile`

身份条、个人页与分段门禁都靠它。无参。

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "level": 0, "levelName": "菜鸟", "streak": 3, "streakTarget": 10,
            "hasApiKey": true, "nickname": "小明", "avatar": "/avatars/oXXXX.png" } }
```

| 字段 | 说明 |
|---|---|
| `level` / `levelName` | `0/1/2` 与 `菜鸟/入门/高手` |
| `streak` / `streakTarget` | 当前连对 / 升级所需的 10 |
| `hasApiKey` | 是否已存 Key。`false` 时前端引导用户先填（见 §7.2） |

### 7.2 `POST /api/teach/apikey`

### 7.3 出题与答题

**`POST /api/teach/quiz/next`** — 无参，按身份等级从该级题库抽一题。

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "questionId": "q7f3a1", "stem": "……", "options": ["A", "B", "C", "D"] } }
```

> **绝不能带答案**。正确项与解析只在答题响应里出现，否则前端一抓包就废了连对。

**`POST /api/teach/quiz/answer`** — 入参 `{ "questionId": "q7f3a1", "choice": 2 }`

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "correct": true, "correctIndex": 2, "explanation": "……",
            "streak": 4, "level": 1, "upgraded": true } }
```

- 答对 `streak + 1`；答错 `streak = 0`，**本周期已答对的排除集一并清空**
- `streak` 达到 10 → `upgraded = true`、`level + 1`、`streak` 归零（已是高手则不再升）
- `level` 恒返回**本次请求之后**的当前等级，前端据此刷新身份条

### 7.4 `POST /api/teach/ask` 分级问答

入参 `{ "question": "蘑菇有什么用" }`

```json
{ "success": true, "code": 200, "message": "操作成功",
  "data": { "answer": "……",
            "links": [ { "title": "……", "url": "https://www.bilibili.com/video/BV……" } ] } }
```

- **图鉴内问题**：后端查图鉴数据组装上下文，**不联网**
- **路线类问题**（≥入门，见 §7.0 矩阵；前端目前只把入口开给高手）：
  `links` 走「每日路线」的三级降级链；图鉴内问题的 `links` 恒为 `[]`
- 成功的回答**缓存进 Redis**，key 用问题文本
- 越级问题按 §7.0 的矩阵硬拦

> **2026-09-27 补充（#44 实现口径）**：路线类问题**完全由后端构造链接、不调大模型** ——
> 模型不能联网（CONTEXT.md「每日路线」），也就不需要用户的 Key。因此它有两点与上面通用规则不同：
> ① **不进回答缓存**（链接里带**当天日期**，缓存到明天就是过期链接）；
> ② **不受 `guide.ai.enabled` 开关影响**（该开关管的是大模型那条路，链接构造不走它）。
>
> 三级降级链的三个触发条件（票面 AC 要求三级都能演示）：**拿到投稿** → 发布时间最新的**具体视频**；
> **够得着 UP 主空间但没有可用投稿** → 该 UP 主的**空间内搜索页**；**一个都够不着**（风控/网络失败）
> → **B站 全站搜索页**。搜索关键词里的日期用**当天真实日期**。

### 7.5 错误码

| 场景 | code | message |
|---|---|---|
| 没带 token | `401` | 未登录 |
| 没存 Key | `-100` | 请先填写你的 DeepSeek API Key |
| DeepSeek `401` | `-100` | API Key 无效 |
| DeepSeek `402` | `-100` | API Key 余额不足 |
| DeepSeek `429` / `503` | `-100` | AI 服务繁忙，请稍后再试 |
| DeepSeek `400` / `422` / `500` | `-100` | AI 服务异常，请重试 |
| 越级提问（内容层，HTTP 200） | `403` | 见 §7.0 文案表 |
| 等级不足（路径层，HTTP 403） | `403` | 当前等级不足 |
| 出题 JSON 解析连败两次 | `-100` | AI 出题失败，请重试 |

> **`401` 已进 `ResultCodeEnum`**（`UNAUTHORIZED`）。**2026-09-27 起 Shiro 收口后返回真 HTTP 401**，
> 响应壳 `code=401`、`message=未登录或登录已过期`（见 §0.1 与 §7.0）。前端 `utils/api.js`
> 对 `statusCode === 401` 与 `body.code === 401` 都走 reject，并在 401 时清本地登录态、静默重登。
>
> **`403` 已进 `ResultCodeEnum`**（`FORBIDDEN`）。两个来源两种形态：**路径层**由 Shiro 的
> `RoleAuthFilter` 回**真 HTTP 403** + 响应壳 `code=403` / `message=当前等级不足`（见 §7.7）；
> **内容层**由控制器回 **HTTP 200 + `code=403`** + 按等级分支的文案（见 §7.0）。前端只读 `message`，
> 两种都弹同一句提示，所以观感一致。

### 7.6 演示用跳级（后门）

`POST /api/teach/dev/level` — 无参，把当前用户 `level + 1`（封顶 2），回新的 `level`。

- **仅演示用**：三级演进真要"连答 30 题"才走得完，演示时间不给。
- 前端形态：身份条上放一个**跳级按钮**，**连点三次算升一级** —— 前端本地计数并显示 `跳级 x/3`，
  第三次才发这个请求，成功后显示"成功跳级"、计数归零。
- 它与 `UserController.testInsertUser` 是同一类东西（演示后门，**留着不删**，口径见 §8.4）。

### 7.7 分级入口（按等级拆的路径）

**2026-09-27 整合**：越级门禁的"路径层"落在这两条分级入口上，由 Shiro 的 `roleAuthc` 在过滤链上把关
（见 §7.0）。它们把 §7.0 的矩阵映射成两条**真实**路径 —— 路线类 = ≥入门、速通类 = 仅高手：

| 端点 | 所需等级（Shiro 角色） | 入参 | 出参 |
|---|---|---|---|
| `POST /api/teach/beginner/route` | ≥入门（`beginner`） | 无 | 与 §7.4 同形：`data.answer` + `data.links`（非空） |
| `POST /api/teach/expert/speedrun` | 仅高手（`expert`） | `{ "question": "怎么速通" }` | 与 §7.4 同形 |

- **不过等级门禁**：菜鸟调 `beginner/route`，或菜鸟/入门调 `expert/speedrun` → **HTTP 403** + 响应壳
  `code=403`（Shiro 过滤链拦下，请求不进控制器、不调大模型）。
- `beginner/route` 的链接由**后端构造、不调大模型**（同 §7.4 的路线口径：不进缓存、不受 `ai.enabled` 影响）。
- `expert/speedrun` 走的仍是问答那条链（服务侧注入分级提示词）。
- **前端现状**：「今日路线」按钮调 `beginner/route`，但小程序**只把它开给高手** —— 非高手点了只弹本地弹窗、
  不发请求（#44 票面 AC）。所以 UI 比后端更严：后端 ≥入门，UI 仅高手。
- **`expert/speedrun` 目前没有前端控件**：速通是 §7.0 里的一档能力，需要一个能挂上路径门禁的落点；
  冒烟脚本覆盖它（高手 200 / 菜鸟 403）。

### 7.8 `POST /api/teach/avatar` 头像上传

`multipart/form-data`，字段名 **`file`**；出参 `{ "success": true, "code": 200, "data": { "url": "/avatars/oXXXX.png" } }`。

- 后端把图存到本地 `guide/avatars/`（相对后端进程工作目录，见 `application.yml` 的 `guide.avatar-dir` /
  `guide.avatar-url-prefix`，目录已 gitignore，与图标同理），静态映射见 `config/WebMvcConfig` 的 `/avatars/**`。
- 文件名用 **openid**（白名单收敛防路径穿越）、扩展名沿用上传的（默认 `.png`）——后缀决定 Content-Type。
- 拿到的 `url` 再交给 §7.1 的 `POST /api/teach/profile` 落库。
- 缺 `file` 或文件为空 → `-200`；写盘失败 → `-100`（**不是 500**）。
- `/avatars/**` 匿名可访问（小程序要直接拉图），与 `/icons/**` 同样落在过滤链的 `/**` 兜底上。

> **为什么要真上传**：小程序 `chooseAvatar` 给的是**临时路径**（`wxfile://…`），进程一退就失效，
> 直接落库等于存了个废链接。所以先落后端本地、换一个稳定的 http URL 再存。

> **Q37 的关键事实**：「让大模型自己联网搜」这条路**不存在** ——
> DeepSeek 官方文档把 `web_search` 工具明确标为 *Ignored*，模型的 `tools` 只能由调用方提供。
> 所以链接必须由后端构造，这一条不是设计选择，是能力边界。
