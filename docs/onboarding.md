# 新队友入职指南

读完这一页，你就能拿到代码、开始干活、并且不把别人的工作搅乱。**全篇只需要 20 分钟。**

---

## 第 0 步：账号和权限

1. **注册 GitHub 账号** —— 去 <https://github.com/signup>，用学校邮箱注册。
   注册完**去邮箱点验证链接**，不验证的话后面会处处卡住。

2. **把你的用户名告诉组长** —— 用户名就是 `github.com/` 后面那串。
   注意**不是昵称**，不是微信名，是你在 GitHub 上的那串英文。

3. **接受邀请** —— 组长邀请你之后你会收到邮件，**必须点邮件里的链接接受**，否则你没有权限。
   点完之后在浏览器里打开仓库地址，能看到代码就说明成功了。

> **打开仓库看到 404？** 三种可能：① 你还没接受邀请；② 你浏览器登录的是**另一个** GitHub 账号；
> ③ 地址打错了。先检查前两个。

---

## 第 1 步：把代码拿到本地

> ### 绝对不要点网页上的 "Download ZIP"
> ZIP 里是一堆**死文件** —— 没有 `.git`，不能提交、不能同步、不能合并。用它干活等于白干。

1. **在 IDEA 里克隆**
   打开 IDEA → 欢迎界面选 **Clone Repository**
   （或菜单 `File → New → Project from Version Control`）。
   地址填：`https://github.com/shanchahuaA/guide`
   会弹浏览器让你登录 GitHub 授权，点同意就行。

2. **确认克隆成功**
   IDEA 打开项目后，**右下角**应该能看到一个分支名。看到 Git 相关的图标和菜单就说明连上了。

---

## 第 2 步：建你自己的分支

> **先做一件事：把右下角切成 `dev`。**
> 分支是"从你现在站的地方"长出来的。你必须**先站到 `dev` 上**，再建自己的分支。

1. **切到 dev** —— 点**右下角**的分支名 → 找到 `dev` → `Checkout`。

2. **新建自己的分支** —— 还是点右下角 → `New Branch` →
   名字用**你的拼音名**，比如 `laowang`、`xiaoLi`。
   **不要用中文做分支名**，会在不同系统之间乱码报错。

---

## 第 3 步：做第一次改动并提交

第一次的目标不是写出多好的代码，而是**证明这条管道是通的**。所以做一件简单又安全的事：

在项目里建一个只属于你自己的文件（比如 `docs/members/你的拼音名.md`），写上你的名字和负责的模块。

> **为什么是新建文件，而不是改 README？**
> 新建一个**只属于你**的文件，永远不会和别人撞车。
> 改别人也在改的文件，是冲突的主要来源 —— 第一次先避开它。

1. **提交** —— 按 `Alt+0` 打开提交面板 → 勾选你新建的文件 →
   写清楚这次做了什么（比如 `添加成员说明`）→ 点 `提交(I)`。
   **别写"aaa"、"修改"、"123"**，三个月后你自己也看不懂。

2. **推送到你自己的分支** —— 按 `Ctrl+Shift+K`。
   因为这是新分支，它会问你"要不要在远程也建一条" —— 确认，
   目标应该显示成 `你的分支 → origin/你的分支`。

---

## 第 4 步：交给全组（合并进 dev）

> ### 念一遍菜单上的字
> 合并菜单会完整写出方向，比如 `Merge 'laowang' into 'dev'` —— 「把 laowang 并进 dev」。
> **念不通，就是方向反了。**

1. **切到 dev** —— 右下角 → `dev` → `Checkout`。**确认右下角现在写着 dev。**
2. **先拉取** —— 按 `Ctrl+T`。这一步不能省，否则你的推送会被拒。
3. **合并自己的分支** —— 点右下角 → 找到自己的分支 → 选 `Merge '你的分支' into 'dev'`。
4. **推送 dev** —— 按 `Ctrl+Shift+K`。
5. **切回去，再同步一次** —— 切回自己的分支 → 合并 `dev` 进来。
   这样两边保持一致，下次合并时差异最小、最不容易冲突。

---

## 每天怎么干活

| 什么时候 | 做什么 | 快捷键 |
|---|---|---|
| 开工前 | 切回自己分支 → 把 `dev` 并进来，拿别人最新的成果 | 分支控件 + `Ctrl+T` |
| 写代码时 | **先看一眼**右下角是不是你自己的分支 | — |
| 写完一小块 | 提交，写清楚做了什么 | `Alt+0` |
| 提交后 | 推送到自己的分支 | `Ctrl+Shift+K` |
| 要给大家用 | 切到 `dev` → 拉取 → 合并自己的分支 → 推送 | 见第 4 步 |

---

## 绝对不要做的三件事

1. **不要点 Force push** —— 它会**抹掉**远程已有的提交。这不是解决冲突，是制造事故。
2. **不推 main** —— `main` 上只放能跑的完整版本。你的东西都走 `dev`。
3. **不改别人的文件** —— 看到别人的代码有问题，在群里说，让别人改。

---

## 卡住了怎么办

在群里只说"我推不上去了"，没人能帮你 —— 那等于没说。请**一次给齐三样东西**：

| 给什么 | 怎么拿到 |
|---|---|
| **1. 你现在在哪条分支上** | 截图**右下角**那个分支名 |
| **2. IDEA 底部的输出原文** | 按 `Alt+9` 打开 Git 窗口 → 切到控制台 → 把红字**原文复制**过来（不要复述） |
| **3. GitHub 网页上现在什么样** | 仓库页面的**分支列表**截图 |

> **永远不要把你的 GitHub 密码或验证码发给任何人。** 包括组长，包括任何声称是"技术支持"的人。
> 没有人有正当理由需要你的密码。需要授权时，正确做法永远是走浏览器登录。

---

**出错了别慌，也别删东西。** 我们的 `main` 上有一份完整的历史兜底，最坏的情况也能恢复。
真正会把事情弄糟的只有一件事：**在不懂的情况下反复乱试**。卡住了就停下来问。
