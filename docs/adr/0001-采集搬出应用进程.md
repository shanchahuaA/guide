# ADR-0001：采集搬出应用进程

- 状态：已决定
- 日期：2026-09-28
- 相关：#20（爬虫改写成 Python）、#22 / #23 / #24 / #25

## 背景

图鉴数据来自 PEAK Wiki。早期采集是**应用内的一个包**（`crawler/`）加一个手动触发端点
（`POST /admin/crawl`）：应用既能读库对外服务，也能把数据源的全量数据拉下来、转换、写回库。

演示前决定把采集改写成 Python 脚本（#20）。新旧并存只有一种结局 —— 两套实现各自演化，
而它们要维护的是同一份口径（熟食公式、标签字典、图标文件名规则）。于是必须回答两件事：
脚本与应用内实现在仓库里留几套、旧的手动入口留不留。

## 决策

1. **仓库里只留一套采集实现**：Python 脚本（`guide/tools/`）。Java 侧的采集代码整体删除，
   不留"兜底版本"。
2. **采集的触发也搬出应用**：`POST /admin/crawl` 与其控制器一并删除，应用不暴露任何采集入口，
   变成**只读库对外服务**。
3. **约束：行为保持。** Python 采集写出的六列（`weight` / `icon` / `tag` / `effect` /
   `description` / `achievement`）与 Java 版逐字段一致。这条不是口号，是可执行的验收：
   金标准快照 + `crawl_items.py --check` 逐字段比对，差异逐条列出、有差异退出码非 0。

## 理由

- **采集不是请求路径上的一环。** 它是离线运维动作：要联网拉数据源、要写盘下图标、要逐条
  写库、要删缓存。实测跑一次约一分钟，境外数据源抖动时更久。挂在 HTTP 上意味着一个请求要
  占住 Tomcat 线程那么久，还得给它的超时、重试、并发单独定一套规矩 —— 而它一天只跑几次。
- **写入口不该匿名可达。** 删除前 `/admin/crawl` 落在 Shiro 过滤链的 `/** = anon` 兜底规则上：
  谁能访问到后端，谁就能用一个 POST 触发一次全量重写。要收口就得先给应用补一套后台登录，
  而那是为了一个应用既不擅长、也不该常驻的动作。
- **删掉写路径之后，应用的边界变清楚了。** 数据从哪来、什么时候变，只剩一条路径（脚本）；
  缓存失效的时机也归脚本 —— 它本来就知道自己写了什么、改了哪些 key，不用应用去猜。
- **脚本的形态更贴合这件事。** 命令行、退出码、报告 JSON、`--check` 干跑（不写库不下载）、
  可以用冻结的离线语料复跑（绕开数据源被 Cloudflare 拦的情形）。这些在应用里都要另造。

## 后果

- **跑采集的前置条件变了**：要有 Python 环境（`pymysql`）、要连得上 MySQL 与 Redis。
  反过来，应用启动不再和数据源可达性绑定，采集失败也不会把应用带崩。
- **缓存失效改由脚本直接删 key**（`guide:item:all` / `guide:answer:*` / `guide:quiz:bank:*`），
  口径与 `ItemCache` / `AnswerCache` / `QuizBankCache` 里的常量一致。应用里那三个
  `evict*` 方法因此没有调用方了；方法、语义与测试都留着 —— 它们是缓存组件自己的契约，
  不是采集的附庸。
- **两套字典**：标签与状态效果的中文字典在应用侧（`dictionary/`，响应组装用）与脚本侧
  （写库时的 `nameZh`）各有一份。改字典要两边一起改，两份分叉的后果是「`/api/tags` 说的和
  条目里的标签对不上」。
- **冒烟脚本不再触发采集**：`POST /admin/crawl` 那一步改成"必须 404"的断言，库里的数据
  由上一次采集决定。采集自身的回归在 `guide/tools/test_crawl_items.py` 与 `--check`。
- **图标随仓库发布**（#24）：脚本按同一套文件名规则覆盖 `guide/icons/`，应用只负责把目录
  暴露成 `/icons/**`，两边都不需要为了"图在哪"做额外约定。

## 被否的备选

- **保留应用内采集作为兜底。** 两套实现的口径同步成本，加上一个匿名可触发的全量写入口，
  两条都不可接受；而"兜底"在数据源被拦时也救不了场 —— 该走的是离线语料复跑。
- **保留 `/admin/crawl`，但让它去调那条脚本。** 应用仍要管进程、定工作目录、解析脚本输出，
  而且它依然是匿名可达的写入口。要收口还是要先做后台登录（#5），没省掉任何事。
- **先给入口加鉴权，之后再删。** 中间态要么先欠一套后台登录，要么先扛着一个匿名写入口，
  两头都不比直接删干净省事。
